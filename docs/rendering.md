# 角色渲染与验证

普通摄影模式使用 Built-in 管线中的复现 shader，不要求运行原版 shader。模型、贴图和数据由使用者自行准备；本仓库不提供它们。

## 框架增量与当前验收

以下按阶段逆序记录；旧阶段中的开项以较新的实现记录和 [技术清单](framework-techniques.md) 为准。

### 独立景深采样预算与手动清晰范围

按 PPT127–128 的分辨率无关散景、43→30 次采样和手动模糊范围要求，新增默认关闭的 `BokehDepthOfFieldRenderer`。显式消费覆盖完整画面的正向线性深度，提供手动清晰范围／物理镜头、近远强度、多边形孔径和自定义完整 30／43 点布局；不是未公开原始核的恢复。`OriginalStyleRenderPipeline` 可通过深度回调选择新路径，失败透传、不叠加旧 DOF。旧 43 采样 shader 与旧方法主体保持不变。格式、所有权、时域深度对齐和约 71／96 MiB 的 1080p 自有目标开销见 [DOF 接入契约](bokeh-depth-of-field.md)。

干净 t15／D3D11 构建为 101239932 字节。含实际 GI bundle 的 Player 接受 4879 项渲染／状态检查，其中 514 项新增；原有 4365 条完整 JSON 记录和 1350 张 PNG 逐字节不变。新增检查覆盖物理／手动 CoC、近远强度、54 组孔径核、30／43 整图 gather、前景膨胀不依赖红通道、HDR／alpha、退化尺寸、11 张目标的丢失／别名／释放，以及真实相机后处理回调。手／脸同时位于清晰范围时 RGB 差为零，背景平均变化约 `0.18648`。

256²、512²、512×256、257×193 的 GPU 高斯散景控制包含两档采样；归一化二阶矩差在离散双线性滤波界内，积分能量最大相对差约 `6.26e-8`。对单个平滑辐射控制的 1024 点圆盘参考，30／43 的平均误差约 `0.001878 / 0.002952`；不据此把较低档概括为画质更好。减少 blur gather 的取样数尚不等于测得帧率收益。

两次实际 `Camera.Render` 的原生捕获共检查 22 个 DOF draw、8 个深度面 draw 和 6 个下游后处理消费者，输入和中间纹理的生产／消费字节一致。实际 blur shader 分别为 30／43 次 `sample_l`，Point／Linear Clamp、无继承各向异性。全 22 个附件的 59508 个像素、全部通道参与独立数值对照，无排除像素；相对单一取整模型的最大差约 `0.00073534`，超出本机校准局部采样区间的最大残差约 `2.39e-7`。后者不是原始像素误差。

早期隐式 `tex2D` 被捕获为继承 anisotropy 9，导致导数相关额外模糊；新 shader 改为显式 LOD 0 采样，调用方 Trilinear／Repeat／aniso16 加全局 ForceEnable 的负面控制已与基线完全相同。原生理想双线性参考的早期失败另通过回放探针定位为交叉权重量化，不扩大统一 RGB 容差或删像素。首次导入编译失败、错误物理测试预期和原生工具兼容错误记录均保留，不计入干净构建验收。

旧 Full／Half／无 GTAO 的 18 份原生原始数据保持一致。普通 1920×1080 摄影和真实角色 Planar 的 17 项离屏控制重新验收并查看预览；完整套件的两条历史 active RenderTexture 警告数量未变。完整动态角色／发丝／透明和复杂遮挡质量、自动完整深度适配、其他平台与移动成本继续为开项，整个 P02 及框架尚未标为完成。

### 场景运动与 HDR 颜色 TAA

按 PDF33 的方差裁剪和 ExcludeTAA／NoJitter 要求，新增默认关闭的 `SceneTemporalAntialiasingSettings`。消费实际场景运动／上次几何，以相机实际 framebuffer depth 排除挡在前面的未登记 opaque，提供独立颜色历史和 `OriginalStyleRenderPipeline` 显式替代桥接。旧 TAA shader、旧默认摄影调度不变，不自动启用 jitter。八张 float4 目标、Point 深度射线、HDR／alpha／分类和生命周期契约见 [接入文档](scene-temporal-antialiasing.md)。

干净 t15／D3D11 构建为 101147204 字节；实际 GI bundle 的完整 Player 套件接受 4365 项渲染／状态检查，其中新增 456 项场景颜色 TAA 控制。覆盖同 tick 多次真实 `Camera.Render`、当前／历史对应、实际后处理接入、HDR 64000 级常量、alpha、投影 jitter、分类 2／4／6、Forward 遮挡、刚体自遮挡、alpha 贴图内容更新、双骨混合／blendshape、两相机、漏消费／隔帧、颜色约定变化、极小尺寸、丢失目标、无效输入和禁用清理。

97×97 的自制高频纹理通过实际投影产生 16 个 jitter 位置，与独立相机当次 388×388、4×4 下采样的空间参考比较。预热后的 16 次渲染中，TAA 平均绝对误差为原始当前帧的 **8.96%**、仅去 jitter 的 bilinear 对照的 **18.31%**；相邻帧变化为后者的 **4.00%**。零历史权重与独立 bilinear 当前采样的最大误差为 `5.97e-8`。这里的改善只对应这个高频控制，不代表复杂场景纹理细节或完整动画画质一致。

常量材质的移动／反遮挡最大颜色残留误差 `2.39e-7`，269 个新露出的异身份像素明确拒绝历史；双骨 blendshape 的三次实际形变分别有 605／548／574 个运动像素使用历史。35°／65° 斜面的八个 jitter 相位均保有实际历史支持。早期实现把连续颜色 UV 错当作 Point 深度的采样射线，导致四个斜面相位全部拒绝历史；已改用实际栅格样本中心重建，没有放宽 `.02` 切平面阈值。失败捕获保留。

原生捕获包含三次完整当前 HDR／运动／可见性→三 MRT 颜色历史提交，第三次经真实后处理消费。锁定实际 shader、常量、尺寸及 jitter，当前生产、上次三张历史消费及后续三个 post consumer 的字节匹配。独立双精度 oracle 检查三幅图共 **28227 个像素**、全部颜色／几何／年龄／分类／权重通道，无边界排除；RGB 最大误差 `6.13e-6`，几何 `7.15e-8`，元数据 `1.76e-5`。实际使用历史的像素分别为 7869／7568／7712。捕获 Player 的全部 4348 项检查接受。初始诊断误要求第三次静止生产控制也必须有非零运动，修正为按控制角色分别检查；数值阈值和运行时代码未改，失败诊断保留。

此前 3909 条完整 JSON 和 1346 张 PNG 逐字节不变；Full、Half、关闭 GTAO 三条旧原生路径的 18 份输出／常量原始数据不变，各捕获的 4335 项 Player 检查接受。普通 1920×1080 摄影和真实角色 Planar 的 17 项离屏控制重新接受；四张 TAA／空间对照、摄影和背面反射已查看。无 C#／shader 错误或运行异常，完整 GI 套件的两条历史 active RenderTexture 警告不变。

完整角色分类／服装、ZWriteOff 透明层整合、全舞台动态画质、Motion Blur、FSR 及移动内存／帧时仍未完成。新模块不把这些开项计为 P01 全面完成，也不将八张浮点目标包装成移动优化。

### GTAO 运动重投影与时域稳定

对照 PDF33 的历史拒绝／方差裁剪，以及公开 GTAO 报告 §4.1 的多方向时域采样，新增默认关闭的 `SceneGtaoTemporalSettings`。显式消费上阶段的实际 GPU 运动、上次深度／法线与表面身份，执行六相旋转、四 tap 几何拒绝、reactive 变化拒绝、邻域／方差裁剪及年龄加权累积。仅累积 GTAO；本次主灯 R 与全分辨率胶囊另算，最终 G 仍仅调制间接漫反射。接入、五张浮点目标的成本与生命周期见 [时域契约](scene-gtao-temporal.md)。

干净 t15／D3D11 构建为 101066668 字节，实际 GI bundle 的完整 Player 套件接受 3909 项渲染／状态检查；新增 500 项 temporal 检查，包含 124 组整幅图 CPU 重投影／拒绝／裁剪／年龄对照，最大通道误差 `1.91e-6`。覆盖 Full／Half、相机／投影变化、刚体自遮挡、alpha 更新、双骨混合与 blendshape、两相机交错、同帧连续渲染、隔帧、切镜、参数改变、奇偶／1×1／单行列尺寸、目标丢失、禁用释放及无效输入。主灯 R 非常量且开关 temporal 前后完全一致；胶囊两种组合在历史之后完成，直接光／emission 对照也完全一致。

静止场景每次使用两个切片，与独立相机当次重新计算的 12 切片参考比较。预热后 12 次采样中，Full／Half 的 AO 平均绝对误差分别降至本次未累积值的 **16.12%／24.68%**，相邻次变化降至 **15.39%／16.75%**；六相均值也符合密方向积分对照。移动遮挡物检查显式使用 `.025` reactive 阈值，出现 5894 次强变化拒绝；参考近白区域的最大残留暗度为 `0.02995`。这些是自制场景、指定参数的结果，不代表全角色或完整舞台的闪烁／拖影验收。

原生捕获包含两次完整“粗 GTAO→当前 AO→历史 MRT→RG8→场景光照”提交，锁定实际 shader／常量／尺寸，当前及上次生产到消费的字节完全匹配。双精度独立 oracle 检查每次 9409 个像素及两张 float4 MRT，无边界排除：AO 最大误差 `1.83e-7`，年龄／权重最大误差 `1.11e-5`，法线／身份最大误差 `5.97e-8`；实际使用历史的像素为 8450／7780。原生捕获 Player 的全部 3885 项检查接受。

早期插值 UV 的往返误差影响边缘历史年龄，未中心化方差也出现白色附近消减误差；改为 SV_POSITION 整数像素运动及中心化矩，保留原 `1e-4` Player 阈值。初始私有 RG8 诊断误用 `.5` 整数 ULP，按 [D3D11 float→UNorm 规范](https://microsoft.github.io/DirectX-Specs/d3d/archive/D3D11_3_FunctionalSpec.htm#3.2.3.6%20FLOAT-%3EUNORM) 的 `.6` ULP 修正诊断，没有更改输出或放宽 Player 阈值。主灯负控也曾因灯光为零而被裁掉，已修正为非零灯光并要求真实暗像素；失败证据保留。

此前 3409 条完整 JSON 和 1344 张 PNG 全部不变。旧 Full、Half、关闭 GTAO 三种原生路径的 shader／常量及共 18 份原始输出逐字节不变，各捕获的 3879 项 Player 检查均接受。普通 1920×1080 摄影和真实角色 Planar 的 17 项离屏控制重新接受；摄影、背面反射及两张 AO 预览已查看。无 C#／shader 错误或运行异常，两条历史 active RenderTexture 警告不变。TAA／Motion Blur 消费、自动脚部胶囊、完整动态场景和移动性能仍未完成。

### 场景 GPU 顶点快照与运动对应

对照 PDF17／32–33 的运动／深度及历史消费要求，补齐显式场景层的物体运动数据前置。`SceneMotionSettings` 默认关闭；geometry shader 从实际 `DrawRenderer` 顶点流保存世界位置／法线，随后输出运动 UV、上次正视深度、有效性和稳定表面身份。上次快照按成功相机渲染交换，不依赖 Unity 游戏循环帧号；支持按需相机。契约、资源成本和桌面后端限制见 [场景运动](scene-motion.md)。尚未将这些数据接入 AO／TAA／SSR 历史或 Motion Blur，不能记为时域稳定性完成。

干净 t15／D3D11 完整构建为 100958412 字节。实际 GI bundle 的完整 Player 渲染／状态套件接受 3409 项检查，其中新增 195 项运动检查。44 组独立 CPU 对应控制覆盖刚体、相机、投影、可变顶点、baseVertex 子网格、混合双骨、blendshape、非均匀根缩放／父级剪切和 shader 顶点缩放；运动／深度最大误差 `4.77e-7`，上次法线最大误差 `1.85e-7`。还核验 alpha 真孔洞与场景 coverage 一致、两表面重排身份、双相机隔离、reset／切镜、拓扑／alpha 修改、丢失目标、resize、隐藏重登及资源释放。

原生 GPU 捕获包含两次完整快照→运动 MRT→场景绘制，锁定实际 shader、常量、4×2 RGBAFloat 顶点纹理与 97×97 运动 MRT，前次生产和后次读取字节完全一致。独立双精度栅格／插值核对两幅图各 9409 个像素、2750 个覆盖像素，无边界排除；运动／深度最大误差 `3.28e-7`，法线／身份最大误差 `1.48e-7`。捕获 Player 的全部 3387 项检查接受，包括捕获内两次 CPU 数值对照。

早期 CPU `BakeMesh` 快照存在缩放重复应用、根骨基坐标及实际渲染更新时间不一致，已经整体替换为实际 GPU 快照。测试还修正了非均匀根下的蒙皮法线模型，以及 [D3D11 §3.4.1](https://microsoft.github.io/DirectX-Specs/d3d/archive/D3D11_3_FunctionalSpec.htm#3.4.1%20Coordinate%20Snapping) 要求的 8 位子像素坐标吸附；原来的 `5e-5` 运动、`1e-4` 法线阈值未放宽。失败构建与捕获保留为排除证据。

此前 3214 条完整 JSON 记录及 1344 张 PNG 全部不变。默认关闭运动的实际 Half GTAO 捕获中，八份几何／粗接收点／常量／可见性／最终 HDR 原始数据逐字节不变；该捕获的全部 3379 项 Player 检查接受。普通 1920×1080 摄影与真实角色 Planar 的 17 项离屏检查重新接受，摄影、背面反射及两张运动预览已查看。无 C#／shader 错误或运行异常；两条历史 active RenderTexture 警告不变。

### GTAO 半分辨率与几何引导空间重建

按 PDF10／19 的低分辨率及环境遮蔽调度，以及 [公开 GTAO 技术报告 §4.1](https://www.iryoku.com/downloads/Practical-Realtime-Strategies-for-Accurate-Indirect-Occlusion.pdf)，新增默认不启用的 `SceneGtaoResolution.Half`。实际生产最近正深度的 2×2 粗接收点及 GTAO，随后通过 4×4 空间／双切平面／法线权重重建，无兼容样本时回退到当前点完整 GTAO。主灯 R 与世界胶囊保留全分辨率，旧默认 Full 和关闭路径不分配粗目标。接入及资源成本见 [GTAO 契约](scene-gtao.md)。

最终 t15／D3D11 干净完整构建为 100915636 字节；实际 GI bundle 的完整 Player 渲染与状态套件接受 3214 项检查，其中 199 项为本阶段新增。24 组逐像素 CPU 重建对照覆盖奇偶尺寸、1×1／单行／单列、透视／偏移投影、斜面、薄边缘、裁切、移动、阈值变化和世界缩放，最大 RG8 误差 `0.002197`。一像素穿孔场景明确触发 11408 个无支持接收点的全分辨率回退；斜面负控仍完全可见。

原生 GPU 捕获确认实际 65×65 RGBAFloat 粗目标、129×129 全分辨率几何／RG8、正确 shader 变体和参数，以及生产到最终光照消费的顺序与原始字节一致性。独立解析阶梯几何、双精度 horizon／胶囊积分及重建核覆盖全部像素：3844 个粗接收点、15129 个全分辨率接收点；最终 G 最大误差 `0.002188`（`0.557721` 个 UNorm 整数 ULP），没有排除边界像素。997 个像素相对 Full 的 GTAO 改变超过 0.01，确认实际进行了重建。

粗浮点 AO 相对理想积分最大差 `0.000013811`。初始私有诊断的 `1e-5` 假设过严；实际 DXBC 将 acos 展开为多项式，全 horizon 域角误差约 `0.000067527`。另一个仅按当前采样点估计误差的诊断也被拒绝。最终显式采用整个角域的 `6.8e-5` 误差包络加 `1e-5` 算术余量，同时保留各失败报告与实际数值；这不是 GPU 精度的形式证明。Player 与最终 RG8 验收阈值未放宽。

首轮测试还发现 CPU fixture 对离屏纹理读回重复翻转行坐标；原生粗点 XY 证明了方向约定，修正的是测试，运行时 shader 未改。此前 3015 条完整 JSON 记录和 1342 张 PNG 全部不变；旧 Full GTAO 及关闭 GTAO 的 ScreenShadow／胶囊原生几何、常量、RG8 和最终 HDR 字节全部不变。三次最终原生捕获各接受无 GI bundle、含捕获请求的 3184 项渲染／状态检查。普通 1920×1080 摄影及真实角色 Planar 的 17 项离屏检查接受，四张本阶段预览已查看。无 C#／shader 错误或运行异常，两条历史 active RenderTexture 警告不变。

此阶段增加了粗纹理和一次 draw，仍保留全分辨率几何；不能声称总显存减少或实测 GPU 加速。时域抗闪烁、隐藏几何／真实厚度、全角色接触及移动平台成本仍未完成，完整 P05 和 A/E/P/O/C goal 继续推进。

### 场景 GTAO horizon／余弦积分

按 PDF13／17／19 和 PPT126 的环境遮蔽位置，新增默认关闭的 `SceneGtaoSettings`，独立实现视轴切片、双向 horizon 查询与余弦角积分。使用实际场景几何预通道，支持世界半径、像素范围限制、法线 bias、远端淡出和可选薄物体 horizon 衰减；输出与 Capsule AO 按相乘或最小值合并进 RG8 G 通道。实现依据 [公开 GTAO 技术报告 §4](https://www.iryoku.com/downloads/Practical-Realtime-Strategies-for-Accurate-Indirect-Occlusion.pdf)，没有使用 Amplify 插件或原版 shader。接入、数学模型及标量合并局限见 [GTAO 契约](scene-gtao.md)。

## 渲染控制

启动摄影模式后按 **F8** 打开角色渲染面板。它独立于动作、面部和物理调度。

- 描边：使用模型切线中的平滑法线及打包顶点色中的宽度、颜色、深度偏移；保留材质禁用描边的标记和 `_ZWrite` 设置。
- 眼部前发覆盖：只在眼白/眉眼的 stencil 区域补画头发。Base 的 A 是视角淡出遮罩，配合材质 `_FadeParam` 与动画头部方向控制透明度，并非直接当作 opacity。其他区域保留不透明头发的深度与混合规则。
- Override material Layer：勾选后用 Sweat / messy layer 滑条临时调整汗液／凌乱层强度（0–1）。只作用于当前角色已启用 Layer 且具有贴图的复现材质；没有可用材质时控件禁用。关闭后恢复各材质原有权重，与光照覆盖独立。
- Override story lighting：临时覆盖光照；关闭后恢复剧情/摄影参数。可调相机相对或世界空间主光、明暗边界、阴影颜色混合强度、光滑度、环境光和附加光强度。
- Override view-space rim only：独立调整相机空间边缘光的方向、锐度、表面染色、RGB 和强度，不必覆盖主光或剧情阴影。控件位于面板下方，可滚动查看。
- Toggle two test lights：添加/移除两盏演示点光源。Unity 场景中的点光和聚光会被角色采样，最多取距离角色最近的 8 盏；不包含灯光 cookie 或附加灯阴影。

Inspector 中 `ActorRenderControls` 还提供有色主光、阴影乘色/加色、有色边缘光、附加镜面光强度和描边宽度。描边默认宽度是摄影棚设置，不宣称适用于原游戏所有镜头。

材质的 Layer 使用第二套 UV：贴图左半部控制基础色，右半部控制 Definition；同一个权重同时作用于两部分。Definition 的 G 为光滑度，B 为金属度（面部用作三角区遮罩），A 为高光强度。禁用 Definition 贴图时使用材质常量。

Layer 的 shader 混合原先已存在，F8 仅提供可逆的使用入口；具体呈现汗滴还是其他细节取决于自己的贴图。刷新角色、换装或禁用控制器会释放旧材质覆盖；覆盖期间观察到的后续脚本权重会保留用于恢复。此设置不写入资产或剧情文件。

### CEDEC 对照增量：Sphere Fog

独立 CPU 预期采用解析正交投影求取样点，检查两个相机姿态（含倾斜和滚转）、两个法线、两个光向量及两组光滑度/金属度，并覆盖身体、发饰、眼睛和脸部的材质差异及零遮罩。旧 shader 在 16 项世界光检查中失败；相同 C# 程序集的修正版通过完整 375 项 GPU 检查。已有 UV/RampAdd 比例测试使用非退化的相机相对正面光，角度由独立检查验收，不放宽浮点容差。

默认固定镜头的当前 HDR、ActorData、时域结果、模糊及 bloom 与旧版及重复捕获逐位一致。两版普通摄影、剧情和各 50 张模型探针完成，世界光输入及状态恢复检查通过；转向、抬俯视画面已检查。这是主光坐标约定修正，没有原版世界光整帧参考，不代表整体视觉或连续动画已追平，也不消除此前间歇性的时域失败记录。

### 闭眼时的眉眼高光

补齐文章第 3.9 节的 type 6 高光：只对两个 UV 分量都严格大于 `0.96875` 的小区域，额外叠加两倍已经过 ramp 的颜色，再接受反光染色和主光乘色。该项不依赖 Definition.A 的普通高光遮罩；恰好位于边界、其他材质，以及共用 type 6 的颈部／脸部其他区域均不应被整体提亮。本地实际绑定的 type 6 shader 也包含这一 UV 门控与加法贡献。

同一 t15 编辑器完整构建旧、新 shader，两版 C# 程序集相同。新增 48 项 GPU 检查覆盖严格 UV 边界、非目标材质、零／非零 Definition.A、RampAdd 染色、已知 ramp 输入及恢复；旧版四项目标区域检查失败，修正版完整 582 项检查通过。真实模型闭眼时高光提亮，睁眼恢复后的同进程图片逐位相同；静态对照明确采样动作并停止时间，不代表连续动画验收。跨进程睁眼图仍有 682 个差异像素，不能把闭眼整图差异全部归于此修正。

普通摄影、剧情 19.90 秒定点捕获和 55 帧角色探针已运行并检查，暂停姿态与恢复播放检查通过。固定参考镜头的当前 HDR、ActorData、时域、模糊及 bloom 与旧版、重复捕获逐位一致；尚无原游戏闭眼整帧对照，不据此宣称眉眼或整个博客完全追平。

### 表情关联的眼睛序列帧

兼容的面部 `MotionDefine.effects` 可关联 `CampusActorMaterialEffect` 数据：用 `materialName` 匹配当前脸部材质，替换颜色／阴影／Definition 贴图，并按 `tileX`、`tileY`、`tileFPS` 播放图集。例如资产自身定义的星星眼会随对应表情自动出现，不需要手动改 shader。必须自行提供动作及其效果依赖 bundle；仓库不附带图集或角色数据。

复现采用左上起、逐行排列的图集，按动作时间取帧；剧情暂停不会继续换帧，跳转可重现对应帧。正数 `duration` 为起点包含、终点不包含的有效区间；零时长持续到该面部动作失去所有权。同一材质有重叠效果时取最后一个有效项，切换表情后恢复原材质。贴图不做跨表情淡入淡出。这些是当前明确的复现约定，尚未确认所有原生 Playable 的时序、循环和混合语义；未实现其他种类的 MotionEffect。

真实剧情已验证现有 3×3、10 fps 星星眼及配套高光替换：九格与回绕、暂停保持、短时恢复播放、回跳到效果之前均有运行状态记录。颜色／阴影／Definition 三路采样另用生成图集作 GPU 检查；只移除图集 UV 变换的同程序集对照会被拒绝。该镜头仍有独立的背景显示问题，不将眼部效果验收当作整场景验收。

### 正交投影下的角色光照

对应角色渲染文章中区分透视／正交观察方向的处理。Unity Camera 设置为正交投影时，公共角色 shader 现在使用平行的相机观察方向，供 ramp、头发高光、RampAdd、反射、附加镜面光及前发淡出使用。此前仍用相机位置减去像素位置，造成正交镜头沿观察轴移动时，画面大小不变而材质光照改变。默认透视表达式保持不变；本项没有新增相机 UI。阴影仍保留独立的距离淡出，不能据此要求整个画面完全不随相机距离变化。

完整 Player 新增 48 项实际 GPU 观察方向检查和八项透视非恒定响应控制，覆盖两种相机姿态、两种法线、两种距离和三个像素位置，最大通道误差 `2.27e-6`。五处旧 CPU 预期公式也改为按投影类型计算观察方向；输入与 `1e-5` 容差不变。使用最终相同 C# 程序集的旧 shader 在 24 项新正交检查和 45 项已有光照／前发检查中失败；修正后完整 1225 项渲染／状态检查通过。

真实模型另用无后处理／描边的浮点相机隔离着色，保留普通表面和前发覆盖。在单独固定阴影为中性的控制中，四个角度的正交近远距离比较，有三个角度整图逐位相同；另一角度仍有一个像素超过 `1e-5`，最大差 `1.69e-5`。透视恢复检查也有小量浮点差异，严格逐位恢复未全部通过，未放宽标准。普通摄影、剧情 19.90 秒定点及 55 帧探针已检查；固定透视捕获仍有间歇性 HDR／时域差异，不宣称整帧或完整博客追平。

### 普通环境反射的坐标

对应[角色渲染文章](https://zhuanlan.zhihu.com/p/1908718263602489063)第 3.8 节。普通摄影棚／剧情使用本地世界朝向的 Cubemap；服装等 type1 材质和眼睛现在与其他材质一样，直接用世界空间反射方向采样。此前这些材质仍套用了私有截帧资源专用的旋转／轴交换，导致同一环境中的反射方向不一致。专用变换只在实际加载对应截帧环境资源时启用；加载失败后的本地环境也不会沿用它。没有改环境颜色、强度、BRDF 或曝光。

完整 Player 自检使用独立生成的六面有色 Cubemap，覆盖五种材质、普通／截帧坐标以及关闭反射后的恢复：60 项采样和 60 项恢复检查成立，最大通道误差 `7.45e-9`。相同 C# 程序集的旧 shader 在十项普通环境方向检查中失败，截帧方向控制仍成立。真实模型正面近景、全身及侧面检查中，关闭环境反射后旧新版画面相同，各自恢复强度也恢复原图；本套默认环境下变化较小，未据此宣称整体反射观感已追平。

普通摄影、剧情 19.90 秒定点及 55 帧探针完成，静态恢复与暂停绕视／继续播放检查成立。固定截帧对照仍有 90 个当前 HDR 像素差异，时域也有差异；修正版重复捕获当前 HDR 相同、时域有 38 个像素不同。辅助数据、模糊和 bloom 相同。保留这些失败，不宣称整帧无差异或全部环境反射已与原版对齐。

### 可选 Matcap 反射

补齐角色渲染文章第 3.17 节的 ReflectionSphere 分支：此前虽然读取了贴图和开关，但采样函数没有接入最终颜色。现在按相机朝向的法线采样，支持透视与正交相机，保留 HDR 解码、Definition.A／阴影可见度和 RampAdd 染色；发丝仍不叠加常规反射，发饰可以使用。此项不替代已有 Cubemap 反射，也不改曝光或默认光照。

在自己的角色材质上设置 `_ReflectionSphereMap`，将 `_UseReflection` 设为 1；普通线性 RGB 贴图使用 `_ReflectionSphereMap_HDR=(1,1,0,0)`。后者四个分量依次为倍率、解码指数、保留项、Alpha 权重。导入兼容材质时识别 `_USE_REFLECTION_SPHERE`、`_EnableReflectionSphereMap` 或显式 `_UseReflection`，仅存在贴图不会自动开启效果。缺少贴图时关闭；明确启用的纯白或纯黑贴图仍有效。

新增无资产检查覆盖两种相机、两个法线、三个解码设置、身体／眼睛／发饰、零遮罩、发丝排除，以及材质开关、解码参数和贴图的传递。它们验证生成输入下的采样与合成，不是原游戏整帧反射对照；常规摄影与剧情数据没有开启该分支，不能把该功能补齐描述为默认画面的反射误差已消除。

实际 D3D11 Player 的新增 78 项 Matcap 检查通过；使用相同测试程序集、旧 shader 的对照在 36 个反射颜色案例中按预期失败。真实模型的生成贴图开／关检查覆盖两个角度，均产生非零衣服反射响应，关闭后恢复原图。普通摄影、剧情 19.90 秒时点截图及 55 帧角色探针完成，暂停绕视保持姿态，恢复播放后时间正常推进；剧情检查采用定点捕获，不代表连续播放约 20 秒或覆盖完整剧情。

接通效果曾使带屏幕阴影的 ForwardBase 变体超过采样器上限，编辑器仍输出了构建成功。现将同为双线性／Clamp 的两份内部环境数组共享采样状态，保留屏幕阴影变体及 Matcap 的独立采样设置；最终构建日志无 shader／C# 编译错误，`studio.py build` 也会拒绝此类“成功但变体编译失败”的结果。最终固定镜头的当前 HDR、ActorData、时域、模糊、bloom 与上一已发布版本及重复捕获逐位一致。修正前曾有 3 个 HDR、8 个时域像素差异，失败记录保留，不以最终相等结果替代此前证据，也不据此宣称整个博客已追平。

### 当前编辑器构建

工程版本及编辑器生成的配置已同步到 t15，历史 t12 源码基线仍保留。t15 随附的 URP 构建预处理器会把正常 Built-in 工程的空 URP 管线列表当作错误；普通构建期间临时关闭 URP 的未使用变体裁剪，结束后在 `finally` 中恢复并保存原值。该调整保留更多变体，不激活 URP、不更改运行时管线；原版 shader 研究构建不采用此开关。已有完整普通 Player 构建和 GPU 运行验证，未据此宣称原版研究管线已兼容。

### 睁眼状态下的前发覆盖

已使用已有表情输入检查睁眼角色的正面、斜侧面与侧面：斜侧面关闭前发覆盖后，原先被发束半遮挡的眼睛露出；开启后恢复覆盖。探针现在记录实际 `expression` 名称，便于识别所选表情，但名称本身不保证截图时没有眨眼，仍需检查图像。

早期无资产自检通过真实相机和补充 pass，检查正视、斜视、侧视及抬俯视基底下的 Base.A 淡出、区域外的不透明头发、覆盖开关及前景遮挡。但那 28 项检查仅使用眼白的 stencil 位，未覆盖实际眉毛位和前发的深度所有权，不能代表完整的头发合成已正确。

本轮睁眼模型探针的静态恢复检查通过；另一组跨进程固定参考捕获中，当前 HDR 和辅助数据相同，时域缓冲仍出现少量差异。该失败保留，尚未证明完整后处理链路逐位稳定。

### 眉毛区域的前发与描边合成

实际 GPU 绘制对照确认了另一处穿透：普通头发在眉毛的模板值 72 处按规则不画，旧覆盖 pass 又只接受眼白位 4，漏掉眉毛位 8；该处未写入头发深度，后侧描边便直接盖住眉毛。覆盖 pass 现在使用材质的 Ref/ReadMask 做 `Ref < masked stencil` 比较，与不透明头发互补；保留模板值，按 `_ZWrite` 写入深度，即使前发颜色完全淡出也不让自身描边穿出。提交顺序改为非头发描边、前发覆盖、头发描边；不改淡出曲线、颜色、描边宽度或物理。

同一 t15 编辑器的旧、新 Player 使用相同测试输入：新增 14 项 GPU 检查覆盖眉毛/眼白/其他模板值、无关高位、零与半透明前发、后侧描边及显式关闭深度写入。旧版失败 6 项，修正版完整 428 项检查通过。原始绘制在问题点先补写前发深度、随后拒绝后侧描边，已由离线 GPU 绘制前后缓冲确认；没有仅凭辅助分类或原始贴图调试颜色判断穿透。

固定输入下当前 HDR 改变 1065 像素，辅助数据不变；头发重叠区域亮度 MAE 从 0.011455 降至 0.010770，脸部及服装区域不变。修正版的五项缓冲在此次独立重复中相同，不撤销历史时域间歇性失败。两版普通摄影、剧情及各 55 帧模型探针完成，包含后视和暂停/恢复检查；此修正没有验收持续播放的后脑动力学，也不代表全部发丝差距消失。

### 角色阴影的亚纹素过滤

阴影比较使用严格深度比较，并按接收点在阴影纹素内的位置计算过滤权重。此前固定的 3×3 权重只对应纹素中心；现在以相同的九次深度采样实现四个半纹素偏移双线性比较的数学权重，保留投影、投射偏移、距离淡出及剧情阴影强度。关闭阴影时显式跳过计算，避免未设置贴图尺寸产生非有限值。

同一 t15 编辑器及 C# 测试程序集的旧、新 Player，分别用生成深度贴图验证 16 个亚纹素位置与四个纹理边界；CPU 预期独立计算四次双线性比较。旧版在新增的 20 项检查中失败，修正版通过完整 259 项 GPU 自检。普通摄影、剧情检查点和 48 张转向/光照探针已运行并检查，本次固定捕获的五项缓冲重复一致、探针状态恢复无变动。整角色同镜头亮度 MAE 从 0.02751 小幅降至 0.02745；发丝细节与侧面阴影仍有明显差距。本次结果不证明所有动态镜头或此前间歇性时域失败已经修复。

### 阴影偏移的材质遮罩

剧情光照的 `useOffset` 现在按 `max(2 × Definition.R − 1, 0)` 抬升阴影接收值，再应用 `shadowStrength`。它使用面部 Layer 混合后的 Definition；不会移动阴影贴图或改变投射偏移。此前误用中心深度比较结果，无法按材质遮罩减弱已被遮挡区域的阴影。

同一编辑器和 C# 程序集的旧、新 shader，经生成深度贴图检查身体、头发、脸部的亮/暗接收点、遮罩边界、部分权重及零值控制：新增 42 项中旧版失败 21 项，新版完整 301 项 GPU 检查通过。真实模型的偏移量 0/0.5/1 对照保持辅助几何数据不变；默认参数和显式零偏移的五项渲染缓冲与旧版逐位一致。普通摄影、剧情及 48 张探针完成，状态恢复无变动。这是参数语义修正，默认画面未改变；尚无原版 `useOffset=1` 整帧对照，不能据此认定全场景阴影追平。

这一自检覆盖过一个实际回归：面部三角区曾固定使用默认偏移，即使 F8 或剧情已改变明暗边界。现在头部与公共表面使用同一偏移参数，默认值保持不变。自检不证明真实模型、动态遮挡、完整后处理或动画已正确复现。

自检还检查超采样输出的目标归属：正常相机使用窗口呈现目标，临时离屏截图使用自己的目标，截图结束后保留正常相机注册。此前后处理会把离屏截图的最终颜色写入窗口目标，导致保存的 PNG 全黑，即使角色 HDR 已正确渲染；现在只在相机仍使用超采样自有输入目标时重定向输出。该检查不涵盖隐藏窗口或无图形设备的截图。

## 带资产的可重复检查

先完成常规配置和构建。在已设置 `GAKUMAS_PHOTO_STAGING` 的终端运行：

```powershell
& .\unity\output\KotonePhotoStudio.exe --photo-mode --hide-ui --validate-actor-rendering .\LocalAssets\render-check
```

探针保存 55 张 PNG：近景正面/侧面/后侧/背面、描边与前发覆盖开关、明暗边界、世界空间光照（含左右强侧光、侧面和抬俯视镜头，并检查实际光照模式）、近景及全身点光/聚光、有色主光下的附加光、Layer、环境光、全身天光开关、有色边缘光、全身皮肤饱和度及恢复动画后的序列帧，并输出 `rendering-probes.json`（schema `photo-studio.actor-rendering-probes.v2`）。需要自己的兼容数据；不是无资产测试，也不是逐骨骼关键帧编辑器或正式导出器。

静态检查阶段暂停动作，每次截图前清空后处理的时域历史，避免前一组光照或镜头污染下一张图；正常播放的累积逻辑保持不变。以 `01-front` 为基准，逐像素比较三次应当相同的画面：

| 检查 | 图像 | JSON 字段 |
| --- | --- | --- |
| 不改变状态的重复截图（A/A） | `01b-front-repeat` | `repeatChangedPixels`、`repeatMaxChannelDifference` |
| 关闭临时光照覆盖，恢复原参数 | `11-profile-restored` | `profileRestoreChangedPixels` |
| 移除测试灯，恢复原场景 | `13-point-lights-removed` | `lightRemovalChangedPixels` |

三组变动像素均为 0 才通过重复性检查；不一致或必需 pass 缺失时 Player 以退出码 2 结束。缺失、被截断的 JSON 不能算通过。该检查只证明本次进程中这些静态状态的恢复，不证明跨机器一致性或功能的视觉正确性。

全身皮肤检查为 `18-skin-neutral`、`18a-skin-desaturated`、`18b-skin-saturated`、`18c-skin-restored`，依次使用饱和度增量 0、−1、+0.5、0，并记录实际 `skinSaturationDelta`。截图前输入被覆盖会拒绝检查；恢复帧相对中性帧的 `skinRestoreChangedPixels` 也必须为 0。该组刻意包含身体，避免只看脸部近景而遗漏身体皮肤错误；结束后恢复原相机和参数。

全身天光检查为 `15a-fullbody-noambient`、`15b-fullbody-ambient`、`15c-fullbody-restored`，依次使用 GI 强度 0、0.5、0。截图前核对实际 `_ActorLightingScales.x`，恢复帧的 `ambientRestoreChangedPixels` 必须为 0；结束后恢复相机。它检查单次运行内的天光响应和恢复，不保证两次进程停在同一个物理姿势。

全身附加光检查为 `13a` 至 `13g`，覆盖无灯、双点光、双聚光、有色主光、关闭额外镜面光、移除灯光和恢复原参数。每帧核对预期灯数并记录实际 `keyColor`、`profileLightColor`、`lightingScales`；恢复帧相对 `13a-fullbody-no-lights` 的 `additionalRestoreChangedPixels` 必须为 0。跨进程姿势可能不同，只把同一进程内的灯光开关用作静态响应对照。

后视检查为 `05b-rear-quarter` 至 `05f-other-rear-quarter`，包含背面关闭描边、关闭前发覆盖的控制。正后方相机距离为 1 m，以免 1.25 m 镜头落到实体摄影棚背景板后面；这不修复普通轨道相机穿过背景板的问题。从 `01-front` 开始，随后 11 帧必须保持同进程的姿势指纹与动作时间完全相同，且动作图不在播放；报告字段为 `pausedGraphStopped`、`pausedOrbitPosePreserved`、`pausedOrbitComparedFrames`。最后 12 张 `motion-*` 恢复播放，`animationResumed` 要求图正在播放且序列内观察到动作时间前进，允许短动作循环绕回。这些条件也参与退出码判断，不能仅凭静态图片恢复相同而通过。

历史运行曾观察到少量单通道 `1/255` 级静态差异；探针保留这些失败，不用容差把它们改记为零。静态探针同时令 `Time.timeScale=0`，普通摄影的暂停不改变全局时钟；这组姿势检查不等于全部物理、跨进程或跨机器的确定性导出承诺。

需要定位差异时追加 `--trace-rendering-stability`。它在正面、正面重复和恢复光照三张图旁保存 ActorData、当前 HDR、时域结果、模糊及 bloom 的原始缓冲和尺寸元数据，用于区分差异发生在哪个阶段；文件体积较大，只应保存在被忽略的本地目录。每张图的 `actorPoseDigest` 是当前进程内角色层 Transform 世界矩阵与蒙皮 blendshape 权重的 SHA-256 指纹。它包含实例 ID，不能跨进程比较，也不包含静态网格顶点或材质状态；指纹变化本身不能证明可见姿势或画面发生变化。新增追踪不冻结或改写骨骼求解。

检查实际图像和 pass 数，不能仅以进程退出码或“画面不黑”验收。眼部遮挡还应选一个睁眼表情，检查侧视时眼睛、高光与前发的关系。不同机器上的动画时刻、动态解算和时域累积不保证逐像素确定性。

### 暂停转镜头时的后脑头发错位

旧暂停仅将动作根 playable 的速度置零，LookAt 动画作业仍会随镜头重新求解头部。在冻结物理的静态探针中，头部发生转动，而头发仍使用上一姿势的世界空间模拟状态，导致后脑大面积露出、发片折叠。普通摄影暂停现在同时停止动作图求值，恢复时重新播放；未关闭头发物理、隐藏脸部或修改材质。剧情暂停仍交由剧情播放器处理，手动动作采样仍保留显式 `Evaluate`。

同一 Tuanjie 2022.3.62t15 编辑器完整构建旧逻辑对照与修正版。旧版在新增后视检查中重现破损，11 帧转镜头检查有 8 帧姿势改变，退出 2；修正版 11 帧姿势和动作时间不变，背面与两侧后视已目视确认大面积露头消失，恢复播放后的动作时间正常推进。完整 55 帧探针的六组静态重复/状态恢复均为零变动像素；396 项无资产 GPU/输入检查、普通摄影及剧情 19.90 秒检查点也已执行。

另用私有诊断构建保留普通 UI 暂停时的全局时钟，头发物理继续运行。旧版转到背面时头身仍会扭转，修正版后视保持完整；两次诊断均因持续物理运动而未通过静态姿势/像素相等条件（退出 2），没有改记为完整探针通过，也未把这种诊断模式加入公开入口。

固定捕获的五项缓冲在本次修正前后均有变化。修正版第一组独立重复逐位相同；发布前重跑时，当前 HDR、辅助数据、模糊和 bloom 仍相同，时域缓冲有 9 个像素不同（最大 0.001953125），该失败保留。相同捕获顶点流不保证后续姿势与驱动状态固定，不能把这次变化归功于 shader，也不能继续承诺旧捕获哈希不变。此增量只验收已重现的暂停转镜头问题；持续播放的头发动力学、后脑着色及整体博客效果仍未完成验收。此前 50 帧探针没有后视覆盖，历史通过记录不能代表整颗头发已正确。

### 持续播放时的后视约束

继续播放并把镜头绕到背后，会暴露静态暂停探针没有覆盖的问题：旧 LookAt 把全身 IK 的 `clampWeight` 写死为 0，头身会强行向后方目标弯折，连带拉坏头发姿态。现在恢复角色动画设置的构造默认值 0.5；眼／头／身体权重、肌肉限位、迟滞和头发物理保持不变。这个默认值由对应构建的初始化行为确认，尚未逐帧验证原游戏实例是否有额外覆盖。

完整 Editor 构建后，用私有相机观察器连续绕行 24 秒，记录 97 个画面及骨骼样本；另运行相同的普通暂停观察，二者均保持全局时钟和头发物理开启。相同路径的播放对照中，头部相对 IK 前姿势的最大位移由 28.26 cm 降至 8.03 cm，背面停留段由 28.26 cm 降至 5.31 cm；已复现的整颗头向后翻折画面得到修正。这些是本地运行统计，不是原游戏逐帧姿势一致性的证明。

普通摄影、剧情 19.90 秒检查点及原有 55 帧渲染探针重新执行，六组静态恢复均为零变动像素，暂停姿势保持及恢复播放检查成立。观察器未开启时的五项固定捕获缓冲与完整 Player 逐位一致；此前观察器版本出现的 15 像素时域残差仍保留。该轮持续播放另有一个样本出现约 2.1 mm 的发根附着偏差，后续定位与修复见下一节。后脑着色和发束运动仍需继续检查，不能据此宣称头发或博客效果整体验收完成。

### 无物理子步帧的发根附着

逐渲染帧观察进一步确认：旧版 24 秒绕拍记录中的 27 次发根偏差，全部发生在没有执行固定物理子步的帧，最大约 6.76 mm；执行过子步的帧没有此问题。骨骼与模拟缓存一起停留在上一位置，而动画头部已经移动。姿势读取前后的骨骼位置／旋转没有变化，排除了该读取操作造成偏差的解释。

现在仅在呈现时按当前动画根的位置平移整条保持中的动态链，不修改模拟位置、速度历史和持续旋转，也不单独移动根节点而拉长第一段。执行物理子步后，根位置已经同步，呈现偏移自然为零。这个修复保留现有积分器、步长、碰撞和动力学强度。

无资产自检增加两条独立生成链，检查平移、旋转、重复呈现、还原及下一子步后的附着、段向量、旋转和模拟缓存；使用非零速度历史避免把“重置为零”误判为保留状态。旧逻辑在三项附着检查中失败。完整构建后的 24 秒播放观察覆盖 1145 个渲染帧，其中 28 帧没有物理子步，发根最大偏差低于 `2.5e-7 m`；普通暂停下另观察 1140 帧，仍保持附着。物理和全局时钟均未关闭。该证据只确认此帧间附着问题，不代表发束动力学或着色已经与原版一致。

新增 pass 使用独立的 `ActorSupplemental.shader`，由相机在透明物体之前按“非头发描边 → 前发覆盖 → 头发描边”执行。不对每个身体/眼睛材质重复执行头发 pass。这个拆分也避免已安装 URP 的构建裁剪器删除 Built-in shader 中的自定义 LightMode。

## 原版 shader 研究入口的限制

`--original-shader --original-urp` 仅用于本地诊断，不是面向用户的替代渲染器。专用构建入口为 `GakumasPhotoMode.Editor.PhotoStudioBuilder.BuildOriginalShaderReferencePlayer`，输出到 `unity/output/OriginalShaderReference/`，不覆盖普通 Player。

研究构建会启用 URP 以保留其 shader，调度自定义 `VLActor` pass，并跳过 Built-in 的 `OnRenderImage` 超采样显示链。仅把 URP 配置放在 Resources 中、然后在 Built-in 构建运行时切换管线，并不足以得到有效对照。

研究入口会检查当前 Actor 材质是否具有预期的具名 `Forward` pass。原始 shader 的名称仍在、`isSupported` 为真，甚至 `SetPass` 成功，都不能排除已回退到错误 subshader。缺少预期 pass 或未找到原版 Actor 材质时会记录实际 pass 列表并以退出码 3 拒绝对照；这项检查通过后仍需要 GPU 截帧验证。研究构建结束后恢复原来的管线和抗锯齿设置，避免影响普通工程。

当前本地 Windows bundle 的 Actor pass 仍出现错误 shader；RenderDoc 已确认，不能把这个入口描述为成功的原版画面重放。需要进一步解决 bundle/引擎/变体的兼容性。普通复现 shader 不依赖该入口。原版截帧、字节码及研究产物不得加入公开仓库。

### 已验证的私有原生绘制参考

独立的 D3D11 参考已实际执行一个原始眼高光绘制，不经过 Unity 的 bundle 导入。它使用未修改的原始 VS/PS 字节码，以及同一次离线截帧恢复的顶点/索引、常量缓冲切片、贴图、逐槽 sampler、光栅、混合、深度/stencil 和绘制前完整目标内容。不能只在清空的目标上画一次就视为等价：加法混合的量化及遮挡依赖原有场景内容。

在该 3840×2160 单帧中，原生绘制后的两个颜色附件及深度/stencil 原始缓冲均与原始回放逐位相同；重复绘制也相同。跳过绘制时保留绘制前缓冲，移除高光基础贴图后高光贡献消失，辅助附件和深度保持不变。四次原生运行的 D3D11 调试层均无错误或警告。原始回放的独立重复捕获也核对了有效状态和资源内容；结构体未使用的 union 尾部不属于有效 GPU 状态。

该绘制的颜色实际写入 `SV_Target1`，格式为 R11G11B10_FLOAT；`SV_Target0` 是 RGBA16F 辅助数据，不能仅按附件编号判断颜色。直接绘制前后差分得到的 470 个贡献像素及其数值，与此前“原始基线 − 关闭眼高光”的 pre-fog 差分完全相同，支持继续使用此前的隔离参考。

该眼高光验证只覆盖一个原始绘制；下面的身体参考是独立扩展，二者都没有解决 Unity 原始 bundle 的兼容性，也不代表完整场景重放。本地复现仍有已记录的颜色和边界残差。原生研究工具、原始字节码和输入快照均保留在私有工作区，不随公开仓库分发；它们不是使用本仓库的额外依赖。

#### 身体／服装绘制与后续合成

原生参考现已覆盖一个实际不透明身体绘制：71658 个索引、8 个纹理资源（含 Cubemap）、7 个 sampler，保留完整绘制前目标和原始 VS/PS。独立重复恢复的有效状态及输入相同；基线与重复运行的颜色、运动／深度／分类附件、深度/stencil 三项原始缓冲均逐位重现原帧。跳过绘制保留三项输入，移除 BaseMap 改变 740037 个颜色像素但不改变辅助数据或深度；已有眼高光参考也完成相同回归。上述八次原生运行的 D3D11 调试层均无错误或警告。

第一版参考曾在颜色和深度完全相同、调试层无警告的情况下，仍错写全部 887074 个绘制像素的运动向量。原因是漏绑定上一帧位置所在的第四条顶点流；补齐后才满足三项附件逐位相同。保留失败记录，没有忽略运动分量或放宽误差。

本地实际身体 draw 的 BaseMap 全部 12 级 mip 与原始数据相同，顶点 UV 相同，投影后位置差异小于 0.006 个内部像素。两边绘制变化区域的 IoU 为 0.99304，仍有 6218 个本地独有像素；这些边界和前序遮挡差异未被裁掉。单独把原生颜色目标改为 RGBA16F 的格式控制，也保留了重复、跳过绘制、缺贴图和辅助附件检查。

| --- | ---: | ---: |
| 原始场景雾之前 | 0.009397 | 0.005763 |
| 原始场景雾之后、时域之前 | 0.006184 | 0.008818 |

原始存档在雾前后确有颜色变化，其后的 edge resolve 在该帧为逐位恒等操作；当时本地尚未复现场景雾合成。身体参考本身没有改变运行时默认值，也不足以支持直接移除补偿。后续已核对实际雾绘制及目标格式并接入独立实现，结果见上文“场景距离雾与 HDR 目标”；保留此处历史对照，说明为何仅改一个亮度乘数不足以验收。

本轮 RenderDoc 与普通捕获的当前 HDR／辅助数据相同，但时域缓冲仍有 447045 个像素不同，最大通道差 `0.08984375`，后续模糊与 bloom 也不同。上述结论限定在时域之前；没有将捕获观察器、全部后处理或整篇博客记为通过。本轮未重新构建 Player，公开增量仅记录新参考及已定位的阶段差异。

已有原版 GPU 截帧的开发者仍可独立进行离线对照，不必把失败的原版 shader Player 当作参考。旧有 `--capture-gpa-camera-and-quit --use-captured-posed-geometry --capture-presented-window --dump-post-inputs` 诊断入口使用恢复的相机和私有顶点流；替换蒙皮网格后会重新绑定描边与前发覆盖命令。经 RenderDoc 启动本地 Player 时，可追加 `--capture-actor-rendering-pass` 捕获该固定姿势下的一帧；日志中的提交数仍需用实际 GPU draw 和缓冲差分核实。所需原版截帧及顶点流不随仓库提供，该入口不影响普通摄影与剧情的姿势。

离线比较须记录分辨率、相机、几何来源、缓冲格式和对齐方式。像素平移应由轮廓遮罩确定，不能用颜色误差选择最有利的偏移；材质内部与边界、无法确定类别的覆盖层应分开统计。角色平均亮度接近，并不代表逐像素渲染已追平。

### 固定几何不等于固定材质状态

当前捕获姿势入口替换顶点流，但眼高光的 `_BaseMap_ST` 仍来自本次表情采样。与原始截帧比较之前，必须单独核对材质属性和逐材质 property block；不要把输入状态不同造成的位置偏差直接归因于 shader。

可在固定 GPA 捕获命令中追加 `--captured-material-uv <本地 JSON 路径>`，显式恢复对应材质的 `_BaseMap_ST`。此选项必须同时使用 `--capture-gpa-camera-and-quit` 和 `--use-captured-posed-geometry`，不允许在普通摄影、剧情或其他捕获模式中使用。数据格式如下；名称和数值必须换成自己核实的捕获输入，示意值不代表任何角色：

```json
{
  "schema": "photo-studio.captured-material-uv.v1",
  "materials": [
    {
      "renderer": "MyCapturedRenderer",
      "material": "MyHighlightMaterial",
      "baseMapST": [1, 1, 0, 0]
    }
  ]
}
```

输入上限为 64 KiB、32 个材质项。每项必须唯一匹配角色层中已加载捕获几何的活动 renderer 和其材质名称；四个数值必须有限。程序先验证全部项，再写入逐材质 property block，不改共享材质、贴图或表情数据，保留既有属性。重复/歧义绑定、缺失几何、非法输入或截图前 UV 被其他逻辑改写时，退出 3，拒绝对照。成功时在本地 captures 目录写入 `material-uv-*.json`，记录输入文件 SHA-256 和截图前已验证的 UV 状态。它只恢复这一材质属性，并非完整 GPU 状态重放；使用覆盖后的状态时应读取此报告，不能把面部驱动器缓存的 UV 诊断字段当作最终 property block。

名称以运行时 `renderer.name` 和 `sharedMaterials[i].name` 为准；复现材质的名称通常带有 `__photo-toon` 后缀。使用自己的截图输入保存 JSON，不要把私有捕获数据提交到源码仓库。无资产自检同时覆盖非法/重复输入拒绝、未加载捕获几何的拒绝、属性保留和后续写入检测。

一个私人单帧对照验证了这个问题：保持相机、捕获几何和轮廓配准不变，仅在隔离数据中调整贡献眼高光偏移的表情曲线，使运行时 UV 常量逐位匹配原始捕获。高光覆盖区域 IoU 从 0.618 提升至 0.922；原来的三像素纵向偏差消失，没有追加图像平移或调节亮度。重复输出、ActorData，以及关闭高光后的当前 HDR 均逐位不变，差异被限定到该高光绘制。新的显式 UV 入口使用未修改的表情数据，产生了与该对照逐位相同的当前 HDR 和 ActorData；不传选项时原有结果也保持逐位不变。仍有边界和颜色残差，不能据此宣称 shader 已逐像素追平。

隔离加法绘制应在各自管线中比较“基线 − 仅关闭该绘制”的同阶段缓冲，并保留 A/A 和辅助缓冲不变的控制。宽泛的眼部类别遮罩不等于单独的眼高光覆盖区域；后处理输入名称也不保证阶段相同，必须确认它位于时域累积之前还是之后。不同 HDR 格式的量化差异需要单独分析，不能直接用整个人物平均亮度校准掉。

### 已分离的格式影响与相机误差

私有原生参考进一步保持原始 shader 和其余输入不变，仅把颜色目标从 R11G11B10_FLOAT 换成 RGBA16F，并无损转换绘制前颜色。两种格式各自的基线、重复、跳过绘制和移除基础贴图控制均通过，D3D11 调试层无错误或警告；原格式仍逐位重现截帧。该修改只用于控制对照，未改变公开运行时的目标格式。

在共同的 510 像素区域和原有轮廓配准下，同格式控制使本地/参考平均亮度比从 1.00715 降至 1.00116，但亮度绝对误差均值仅从 0.14656 降至 0.14174，覆盖 IoU 也未改善。目标格式能解释相当一部分平均偏差，不能解释主要空间残差，因而没有追加亮度校准。

原始 VS 的无光栅 stream-output 与本地 RenderDoc 的实际 VS 输出又确认：同一眼高光绘制的 1200 个按三角形顺序展开的顶点具有对应的 UV，但旧相机的屏幕位置相差约 2.658 像素和 −1.650 像素（Y 向上坐标）。历史相机提取把带有偏轴投影分量的行向量当作正交基，用转置代替逆矩阵计算位置；这一假设不成立。整数图像配准不能替代正确的相机输入。

### 显式捕获相机输入

固定 GPA 捕获可追加 `--captured-camera-state <本地 JSON 路径>`，保留独立恢复的完整 view/projection。必须同时使用 `--capture-gpa-camera-and-quit --use-captured-posed-geometry --capture-presented-window`，且实际加载了捕获几何；不接受普通摄影、剧情或其他捕获入口。未传选项时保留旧相机近似值，避免静默改变历史基线。该选项不替代 UV 或其他材质状态输入。

JSON schema 为 `photo-studio.captured-camera.v1`，输入限 8 KiB，仅使用可信的本地数据：

| 字段 | 约定 |
| --- | --- |
| `schema` | 上述 schema 字符串 |
| `width`、`height` | 实际渲染目标尺寸，各为 1–16384；超采样时不是窗口尺寸 |
| `nearClip`、`farClip` | 有限、正数，far 大于 near；由捕获相机状态提供 |
| `worldToCamera` | 16 个有限值，行优先的 Unity CPU view；刚性仿射矩阵，观察方向为相机空间负 Z |
| `projection` | 16 个有限值，行优先的 Unity CPU 透视投影；未经过 GPU Y 翻转或深度转换，最后一行为 `[0, 0, -1, 0]` |

矩阵均按列向量相乘，即 `clip = projection * worldToCamera * worldPosition`。程序由 view 的逆矩阵设置相机 Transform，使 shader 相机位置与显式矩阵一致；固定捕获期间关闭轨道控制器，普通摄影/剧情不受影响。投影矩阵是权威输入，不能用目标宽高比重新生成它；相机的 aspect getter 可能由投影重新计算，也须保留。

非法矩阵、尺寸不符、重复/冲突选项或截图前状态变化时退出 3。渲染帧结束后、保存截图前复核目标、Transform、矩阵和镜头状态，成功写入 `camera-state-*.json`：包含输入 SHA-256、应用后的 CPU 状态及实际 `GL.GetGPUProjectionMatrix(..., true)`/view-projection。该报告不能代替 GPU 顶点或图像验证；私有输入及输出均不应提交。

本轮私人单帧实际验证了上述修正：未修改 VS/PS、捕获几何和 UV，也未追加图像平移或亮度拟合。眼高光的 1200 个 GPU 顶点与原始 VS 对应位置最大相差 **0.00166 像素**，深度最大相差 `1.21e-7` NDC；原来的系统性像素偏移消失。原始大世界坐标浮点运算与局部坐标路径仍不保证逐位一致。

在同一 511 像素对照区域，旧相机沿用原有轮廓配准，新相机直接使用零平移：眼高光亮度 MAE 对原始 R11G11B10 参考从 0.14627 降至 0.02624，对 RGBA16F 格式控制从 0.14146 降至 0.01926。仍有颜色/边界残差，尚未证明整个角色或其他材质逐像素一致。在该相机修正阶段，新相机基线重复的当前 HDR/ActorData 逐位一致；不传选项的两项缓冲也与当时旧 Player 逐位一致。后续采样设置修正会改变颜色，不应把这一历史兼容性对照当作永久的图像哈希承诺。

无资产自检新增 30 项相机解析、应用、输入哈希、后续写入和命令行作用域检查，连同已有 ramp、呈现目标及 UV 检查共 49 项在该 D3D11 Player 中通过。真实错误 schema、目标尺寸和 CLI 作用域输入均退出 3 且未生成截图。本轮也检查了普通离屏摄影、剧情 19.90 秒检查点和 32 张渲染探针；此轮静态重复/恢复/移除灯光的变动像素均为 0，不撤销此前记录的间歇性失败。

本轮验证通过替换私有 Player 中本项目的 C# 程序集完成；沿用已有引擎和 shader，没有重新运行 Editor 导入、shader 编译或完整构建。新的相机模块不含原始捕获数值或字节码。

### 采样器与强制各向异性过滤

运行时现在使用 `AnisotropicFiltering.Enable`，尊重每张贴图的设置，不再用 `ForceEnable` 强制升级过滤方式。这项修正用于普通摄影和剧情，不仅限于固定捕获；仍允许贴图自行启用各向异性过滤。

眼高光残差揭示了实际差异：贴图自身报告 Bilinear、aniso=1，10 级 mip 的 BC7 sRGB 数据也与原始截帧逐字节相同，但强制模式下真正绑定的 GPU sampler 是最大各向异性 9。原始对应 sampler 使用双线性 min/mag、最近 mip、Clamp。必须按编译后 shader 的绑定关系检查：本地基础贴图 `t0` 使用 `s1`，不能拿同编号的 `s0` 代替它。

私有控制先排除了绘制前底色的主要影响：仅令原始绘制使用本地底色，同格式 497 像素区域的亮度 MAE 从 0.01981 变为 0.01969，变化很小。原始 GPU 法线转到各自观察空间后最大差异小于 `1.85e-7`，rim 遮罩相同。随后只把原始基础贴图 sampler 换成旧本地各向异性状态，MAE 降至 0.000184，重现了旧本地的采样行为；原始 shader、贴图和其余状态均未修改。

实际修正后，本地 GPU 基础贴图 sampler 恢复为对应的双线性/最近 mip 状态；VS/PS 字节码、GPU 顶点输出和贴图 mip 数据保持不变。在相同格式、匹配各自绘制前底色、零图像平移的 497 像素区域，眼高光亮度 MAE 从 **0.019688 降至 0.000178**，覆盖区域为两侧相同的 487 像素（IoU=1）。仍有少量浮点/采样残差，未宣称逐位相同。直接对原始 R11G11B10 格式的 MAE 仍为 0.00857；不能将同格式控制的结果冒充原格式一致性。

原生参考的原格式回归、重复、跳过绘制及缺贴图控制均保留；本轮这些原生运行的 D3D11 调试层无错误或警告。修正后的固定捕获重复和 RenderDoc 捕获的当前 HDR/ActorData 相同，直接绘制差分也与关闭高光的 HDR 差分相同。普通离屏摄影、剧情 19.90 秒检查点和 32 张渲染探针重新检查；该次重复/恢复/移除灯光均为 0 变动像素，已有 49 项无资产自检通过。本轮仍是私有 C# 程序集重编译，未执行新的完整 Editor 构建。

该证据仅完成一个眼高光材质、一个固定镜头的采样修正验证。其他材质的 sampler、光照、环境反射及整体后处理仍需要各自的原始绘制对照，不能从这一结果推导整个角色已经追平。
